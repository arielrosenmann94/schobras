# SCHOBRAS.CL v1.0 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web informativa de la constructora SCHOBRAS.CL, con catálogo de proyectos administrable y backoffice propio para la dueña. Entrega: lunes 2026-10-26.

**Architecture:**
- Monolito Django que renderiza todo el HTML en el servidor, sin framework de JS. Apps: `core` (base común, configuración del sitio, inicio, SEO), `projects` (categorías, proyectos y fotos), `accounts` (usuario y rol) y `panel` (backoffice).
- Toda escritura de negocio pasa por `projects/services.py`. El panel lo usa hoy y la API de la v2.0 (conector MCP, patrón admindf) lo va a usar mañana: una sola puerta.
- Fotos en Cloudinary en producción.
- Prioridad: Tasks 0–7 (web pública y despliegue) antes que Tasks 8–11 (panel). Mientras no esté el panel, Ariel carga los proyectos desde el admin de Django.

**Tech Stack:** Python 3.12, Django 6.0.6, PostgreSQL (Heroku) / SQLite (local), WhiteNoise, gunicorn, `uuid6` (UUID v7), `django-axes`, `cloudinary` + `django-cloudinary-storage`, CSS y JS propios.

## Global Constraints

- **Idioma:** el código va en inglés (modelos, campos, funciones, nombres de URL). La interfaz, los mensajes y las rutas públicas van en español (`/proyectos/`, `/panel/`).
- **Modelos:** todos usan PK UUID v7 (`uuid6.uuid7`), además de `created_at`, `updated_at`, `__str__` y un `Meta` completo. Heredan de `core.models.BaseModel`. El usuario (`accounts.User`) también usa PK UUID v7.
- **Formularios:** siempre Forms o ModelForms con `fields` explícito, nunca `__all__`. Patrón PRG y `{% csrf_token %}`.
- **Prohibido:**
  - `print()`
  - `except Exception` (salvo en un límite HTTP, con log)
  - `str(exc)` dentro de una respuesta
  - `style="..."` en las plantillas
  - `{# #}` de varias líneas (usar `{% comment %}`)
  - CDNs en tiempo de ejecución
- **CSP nativa de Django 6:** `script-src 'self'` con nonce, `style-src 'self'`, `img-src 'self' data: https://res.cloudinary.com`, `font-src 'self'`, `frame-ancestors 'none'` y sin `unsafe-inline`. Además: `X_FRAME_OPTIONS="DENY"`, `SECURE_CONTENT_TYPE_NOSNIFF=True` y `SECURE_REFERRER_POLICY="strict-origin-when-cross-origin"`.
- **Colores** (como tokens CSS): antracita `#2C3539`, bronce `#B57949`, cemento `#A9ABB6`, blanco `#FFFFFF`.
  - El bronce sobre blanco da 3,6:1: solo se usa en líneas, íconos y texto de 24 px o más. **Nunca** en texto normal ni como fondo de botón con texto blanco.
  - El botón principal va en antracita con texto blanco.
- **Tipografía:** Open Sans autoalojada (woff2 variable, subconjunto latino).
- **Accesibilidad:** WCAG 2.2 AA mínimo, con enlace para saltar al contenido, landmarks, `aria-label` en los botones que solo tienen ícono, `:focus-visible` visible y áreas táctiles de 44 px o más. Diseño mobile-first de 360 a 1440 px.
- **Rendimiento:** JS propio < 20 KB y sin librerías. Toda animación respeta `prefers-reduced-motion`. Sin JS, todo el contenido queda visible. Lighthouse móvil ≥ 90 en rendimiento y accesibilidad, y LCP < 2,5 s.
- **Marca y contenido:**
  - Marca visible: **SCHOBRAS.CL**. Razón social: **Constructora Schonffeldt SpA**. El RUT no se muestra.
  - Regiones, con estos textos exactos: "Región Metropolitana", "Región de Valparaíso", "Región de O'Higgins".
  - "Más de 25 años" siempre se atribuye a los profesionales.
  - Ningún modelo tiene campo de dirección.
  - No van en la v1: Misión, redes sociales, formulario, equipo, testimonios, cifras, dirección, horario, mapa ni analítica.
- **Dependencias:** versiones exactas con `==`. `pip-audit -r requirements.txt` sin vulnerabilidades. Solo se usan las dependencias que aprobó Ariel: `uuid6`, `django-axes`, `cloudinary` y `django-cloudinary-storage`.
- **Git:** Conventional Commits en el formato `tipo(alcance): descripción`, con menos de 20 archivos por commit. **El agente nunca hace `git push` ni despliega.** Eso lo hace Ariel.
- **Definition of Done** de cada task:

```bash
$PY manage.py test && $PY manage.py check && $PY manage.py makemigrations --check --dry-run
grep -rnE 'style="|print\(|except Exception' --include=*.py --include=*.html accounts core projects panel templates  # sin resultados (salvo el límite HTTP documentado)
grep -rn '{#' --include=*.html . | grep -v '#}'  # sin resultados
git diff --check
```

## Review Focus

1. **Proyecto sin fotos.** Un proyecto "publicado" que no tiene fotos, o al que le borraron todas, no aparece en la web pública y no rompe ninguna página. Pruebas en Task 1 (`test_published_excludes_without_photos`) y Task 5 (`test_detail_without_photos_404`).
2. **WhatsApp con formatos chilenos.** "+56 9 1234 5678", "912345678" y "56912345678" producen el mismo enlace. Un número inválido oculta el botón. Prueba en Task 2.
3. **Sin ningún canal de contacto.** No aparecen el botón flotante, el CTA ni el bloque de contacto, y no queda ningún `href="#contacto"` apuntando a la nada. Pruebas en Tasks 3 y 4.
4. **Fotos de celular.** Archivos de más de 15 MB o en formatos que no son JPG, PNG ni WebP se rechazan con un mensaje claro en español y sin error 500. Prueba en Task 10.
5. **Títulos repetidos.** Generan slugs distintos, y editar el título no cambia el slug. Prueba en Task 1.
